1Features

  • 3 styles: full-width bar · corner box · centre of the screen (must be answered first)
  • Shown on every page until the visitor answers; nothing is stored before that
  • Categories: necessary (always on) · analytics · external media (maps, video) · marketing
  • The Reject is as visible as Accept, as regulators expect
  • A small round button in the corner lets visitors change their mind / withdraw consent at any time
  • Consent log: a random ID, the choices, time, page, browser and a hash of the IP (the real IP isn’t stored), kept for 36 months, CSV export
  • Analytics / marketing scripts placed in the plugin run only after the visitor consents · Google Consent Mode v2
  • Other iDev plugins wait for consent: maps (iDev Maps), and popups don’t cover the banner

2Getting started

  1. General settings

    iDevApp › Cookies and privacy › General Choose the style, position, privacy policy page and how many days to remember the answer, and turn on the consent log

  2. Edit the text

    In the tab Text the banner’s Thai / English title and text

  3. Move your tracking code here

    In the tab Categories and scripts paste the Google Analytics / Facebook Pixel code into that category’s box, then remove the old code from the theme The code only runs once the visitor has consented

  4. Adjust the look

    In the tab Appearance background, text and button colours and the Reject button style

When you change the privacy policy, change the policy version (e.g. 1 → 2) and every visitor is asked again

3Consent log

If a visitor asks to see or delete their record, the consent ID is in the cookie idev_consent (the part between the | signs); search for it in the consent log tab

4iDev Cookie Consent Pro (1,900 THB)

The Pro version (one zip with the free version inside) is for organisations that must handle data subject requests and need evidence when audited. Lifetime licence for 1 website; everything works during the trial, but printed documents say TRIAL.

  • Data subject request form (block or [idev_privacy_request]): access / copy, portability, correction, deletion, objection, restriction, withdrawal of consent; fills in the cookie consent ID and sends a confirmation email with a request number
  • Request register 30-day PDPA deadline with overdue alerts, status, identity-check notes, email replies, a full history and CSV export; names and emails are encrypted
  • Buttons to delete the requester’s consent records and start an export / erasure request with WordPress’s own tools
  • Consent receipt per ID: the answer history and the banner / policy text the visitor actually saw at that time; print or save as PDF
  • Evidence report for a period: accept / reject / custom by month, categories, policy versions, a settings check and open requests
  • policy version A copy is kept automatically whenever the text or the policy page changes, with a warning if the policy changed but the version didn’t
  • Cookie and script scan opens your pages like a first-time visitor and shows which of Google Analytics, Facebook Pixel, YouTube, etc. run before consent, and how to fix it
  • Choose how long consent records are kept

Pro needs the free iDev Cookie Consent plugin installed first. The menu is at iDevApp › Privacy (Pro) · this tool helps keep evidence and handle requests; it is not legal advice

5Shortcodes and developers

ShortcodeResult
[idev_privacy_request]Data subject request form (needs Pro)
[idev_cookie_settings]A "Cookie settings" link that reopens the banner (for the footer or the policy page)
[idev_cookie_settings]Cookie settings[/idev_cookie_settings]Your own link text

For scripts you place in the theme yourself that must wait for consent, use type="text/plain" and data-idev-category="analytics" (or external, marketing); for iframes use data-idev-src instead of src

<script type="text/plain" data-idev-category="analytics">
  /* Google Analytics code */
</script>

<iframe data-idev-src="https://www.youtube.com/embed/..." data-idev-category="external"></iframe>

<script>
  // JavaScript: check for or wait for consent
  if (window.idevConsent && idevConsent.allowed('external')) { /* ... */ }
  document.addEventListener('idev:consent', e => { /* the visitor just answered */ });
</script>

PHP: idev_consent_allowed('analytics')
